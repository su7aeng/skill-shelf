# 스킬집 글쓰기 규칙

짧게, 자연스럽게, 한 번만. 보면 아는 건 쓰지 않는다.

## 말투
- 문장은 해요체로 끝낸다. 합니다체·반말 금지. 예외: 요청 예시는 사용자 말투 그대로("~해줘").
- 제목·버튼·배지·탭·표 칸은 끝맺지 않은 명사구로 쓴다. "모두 보기", "후기 쓰기", "검사 통과"
- 제목은 질문형 금지. 예외: 입력을 받는 화면의 제목("어떤 일을 하고 싶으세요?")

## 길이
| 요소 | 최대 |
|---|---|
| 페이지·섹션 제목 | 12자 |
| 버튼·링크·탭 | 8자 |
| 배지·필터 | 7자 |
| 카드·보드 설명, 카테고리 설명 | 한 줄, 25자 안팎 |
| 안내(hint)·리드 문단 | 2문장 |

## 쓰지 않는 것
- 번역투: "~를 통해", "~에 대한", "~하는 것이 가능해요", "~되어집니다"
- "~하는 곳", "~하는 공간" 같은 자기소개
- 설명을 겹겹이 쌓기. 한 문장에 정보 하나.
- 괄호 덧붙임. 약어·명령어 병기만 허용: "관리자 권한(sudo)"
- 느낌표, 이모지, "꼭", "정말", 바뀌는 숫자 하드코딩("2만 개가 넘는")
- 같은 화면에서 "자동으로", "알아서", "쉽게", "바로" 반복. 한 번이면 충분하다.
- 화살표 장식. 뒤로 가기 링크("← 목록")만 허용.

## 숫자·날짜
- 개수는 천 단위 쉼표 + "개": 1,234개. 에이전트도 "개".
- 스타는 카드에서 1.2k, 상세에서 1,234.
- 날짜는 2026-11-09. "며칠 전" 같은 상대 표현은 쓰지 않는다.

## 이름 짓기
- 스타터팩: 사용자가 하는 일 + "~하기". "HWP 문서 다루기", "제품 홍보하기". 막연한 명사("한국 사무 팩", "기본기") 금지.
- 카테고리: 하는 일의 분야를 구체 명사로. "·"로 최대 두 개. "비즈니스", "콘텐츠", "작업 방식"처럼 넓은 말 금지.
- 섹션: 무엇이 모였는지. "추천 스킬", "후기 많은 스킬"

## 고친 예
- 한국 사무 팩 → HWP 문서 다루기
- 작업 방식·생산성 → 계획·작업 관리
- 위험 신호 발견 → 위험
- 이렇게 써 보세요 → 요청 예시
- 하고 싶은 일을 평소 말투로 적어 주세요. 2만 개가 넘는 스킬 중에서 맞는 조합을 골라 드려요. → 평소 말투로 적으면 맞는 스킬을 골라 드려요.
- 요청이 설명과 맞으면 자동으로 불러와요. (15번 반복) → 자동 · /이름
- 각 스킬의 저작권은 원작자에게 있습니다. → 스킬 저작권은 각 원작자에게 있어요.
